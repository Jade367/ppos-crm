## Goal

A pnpm workspace with strict TypeScript, ESLint, Prettier and Vitest, a real (still empty) `@ppos/core` package, and every root script from architecture §13a. After this task, each later task proves its work with one command (`pnpm verify:quick`, `pnpm verify`), CI's `node` job runs instead of skipping, and `packages/core` can be imported both by Vite apps (P0-04) and by Deno edge functions (P0-03).

## Spec

**Root `package.json`**: `"private": true`, `"type": "module"`, `"packageManager": "pnpm@<exact output of pnpm -v>"`, `"engines": { "node": ">=22" }` (`.npmrc` has `engine-strict=true`; a narrower range would break the 22 LTS fallback). Tooling devDependencies live at the root only, exact versions (`.npmrc` has `save-exact=true`): `typescript`, `@types/node`, `vitest`, `eslint`, `@eslint/js`, `typescript-eslint`, `globals`, `eslint-plugin-react-hooks`, `prettier`.

Pick the lint/compiler versions in this order: `typescript-eslint` = npm latest; `typescript` = the newest version inside the `typescript` range of `npm view typescript-eslint@<that version> peerDependencies`; `eslint` = the newest version inside both `typescript-eslint`'s and `eslint-plugin-react-hooks`'s `eslint` peer ranges. Record each range and the URL you read in `versions.md`. Any "unmet peer" warning from `pnpm install` is a failure: fix it by re-pinning, never by ignoring it.

**`packages/core`** (`@ppos/core`)
- `package.json`: `"name": "@ppos/core"`, `"version": "0.1.0"`, `"private": true`, `"type": "module"`, `"exports": { ".": "./src/index.ts" }` (source export; no build), scripts `"test": "vitest run"`, `"typecheck": "tsc --noEmit -p tsconfig.json"`. No dependencies yet.
- `tsconfig.json`: extends the base; `lib: ["ES2023"]` only (no `DOM`, so browser globals do not type-check in core); `include: ["src", "tests"]`.
- `vitest.config.ts`: project name `core`, environment `node`, include `tests/**/*.test.ts` (so `tests/acceptance/*.acceptance.test.ts` is collected once installed).
- `src/version.ts`: `export const CORE_VERSION = '0.1.0';`. `src/index.ts`: `export { CORE_VERSION } from './version.ts';`. `index.ts` is the only public entry (golden tests import `../../src/index`).

- `tests/unit/version.test.ts`: asserts `CORE_VERSION` matches `/^\d+\.\d+\.\d+$/` and equals `version` from `../../package.json` (JSON import with `with { type: 'json' }`; if that import does not type-check, keep only the format assertion and note it in PROGRESS.md).

**`scripts/dev/verify-extra.mjs`** (Node built-ins only, ≤ 120 lines, streams child output, exits non-zero on the first failure, never prints environment variables):
1. Edge functions: no `*.ts` under `supabase/functions` → print `SKIPPED (no edge functions)`. Otherwise require `deno` on PATH (missing → exit 1 with "install Deno 2, see P0-00"), then in `supabase/functions` run exactly what CI runs: `deno check` on every `*.ts` except `*.test.ts` and `node_modules`, then `deno test --allow-env --allow-net --allow-read` if any `*.test.ts` exists.
2. Database: no `supabase/config.toml` → print `SKIPPED (no supabase project)`. Otherwise, if `supabase status` fails (local stack not running) → print exactly `SKIPPED (no local supabase)`. Otherwise run `supabase test db` (only if a `*.sql` exists under `supabase/tests`) and `supabase db lint --level error`. Spawn `supabase` from PATH (`pnpm verify` puts `node_modules/.bin` on PATH; P0-02 adds the pinned CLI).

## Stop and escalate if

- `node -v` or `pnpm -v` fails, or Node is older than 22 (human step P0-00 A).
- A package you need is not in `approved-deps.json` → write a Dependency request in PROGRESS.md; never guess names.
- After reading vitest.dev for the installed major, the multi-project setup is still unclear or fails → BLOCKED with the URL you read and the exact error.
- `pnpm install` fails because of `engine-strict` or peer conflicts that need a protected-file change, or no set of versions satisfies all peer ranges → BLOCKED with the `npm view … peerDependencies` output.
- `pnpm verify:quick` takes longer than 3 minutes (the Stop hook kills it at 280 s) → record timings.
- A guard fails on a file you did not create.

## Hints (verified facts / pitfalls)

- Vitest: `5.x` was the npm latest on 2026-10-11. Our knowledge (verify for the installed major on vitest.dev): Vitest 3.2 added `test.projects` in the root config and deprecated the separate `vitest.workspace` file, and later majors removed that file. Per-package configs use `defineProject` where documented. Do not create `vitest.workspace.*` unless the installed docs say so.
- When an installed major is newer than you know (TypeScript, Vitest, ESLint, pnpm), read its migration guide with the web-reader tool and record the URL in `versions.md` (its header rule). Do not assume old defaults.
- Write the ESLint config as `eslint.config.js` (ESM through `"type": "module"`). A `.ts` config needs an extra loader package that is not approved. Flat-config export names of `typescript-eslint` and `eslint-plugin-react-hooks` change between versions: copy them from the installed package's README.
- `vitest run` exits non-zero when it finds no test files; that is why only `test:acceptance` gets `--passWithNoTests`.
- `pnpm -r run <script>` skips the root package by default, so the root `typecheck` does not recurse into itself.
- pnpm ≥ 10 does not run dependency install scripts by default. If it prints "Ignored build scripts", do not approve them interactively; act only if a tool actually fails, and then escalate.
- Golden tests import `../../src/index` without an extension; `moduleResolution: "bundler"` resolves that. Core-internal imports still use `.ts`.
- CI runs Node 24 and `pnpm install --frozen-lockfile`: commit `pnpm-lock.yaml` in the same commit as every `package.json` change.
- The Stop hook runs `pnpm -s verify:quick` before you end a turn with uncommitted code. Keep it fast: no network, no Docker.
- `Intl` is part of the ES library, so `formatPence` (P1-01) needs no `DOM` lib.
- Run `pnpm format` only after Acceptance 12 passes: protected files cannot be restored through the shell (the Bash hook blocks `git checkout`/`git restore` on them).
- The Read tool is denied on `.env.*` (project settings), which includes `.env.example`, so Edit cannot touch it. Create `.env.example` in one Write; check it with `grep -cE '^[A-Z_]+=$' .env.example` (→ `14`) and `cat .env.example` (the Bash hook allows `.env.example`). If it must change, rewrite it whole with a shell heredoc (`cat > .env.example <<'EOF'` … `EOF`).
